3. 비공개 커밋은 해당 단계의 「비공개 저장소 원문 준비 방법」을 펼쳐 「원문 전달 도구 받기」를 누릅니다. ZIP을 프로젝트 밖에 압축 해제하고, JSON을 저장할 프로젝트 밖의 새 폴더도 미리 만듭니다.
4. 제출할 프로젝트의 Git 최상위 폴더에서 PowerShell을 열고 안내된 student-source-cli.mjs 명령을 실행합니다. 도구·출력 파일 경로를 본인 PC에 맞게 바꾸고 --commit 뒤에 제출할 40자리 커밋을 지정합니다. 도구는 커밋된 원문만 묶으며 학생 코드를 실행하거나 업로드하지 않습니다.

## 최종 커밋의 식별과 이동 가능한 실행

자기 자신의 커밋 해시는 커밋 생성 전에 문서에 넣을 수 없으므로 임의 해시를 쓰지 않습니다. 제출할 40자리 최종 값은 커밋 완료 후 작업 보고에서 확인합니다. 새 복제본에서 그 값을 `git checkout --detach`로 고정하고 `git rev-parse HEAD`와 대조합니다. 최종 실행 결과는 대상 해시·시각·환경을 포함한 별도 검증 로그로 남겨 사전 기록과 구분합니다. 최종 검증 뒤 코드·문서가 변경되면 새 커밋을 만들고 다시 검증합니다.

이 문서를 저장한 커밋에서 코드 변경이 없다는 것은 재검증을 생략하거나 앞선 결과를 최종 성공으로 합쳐도 된다는 뜻이 아닙니다. 최종 로그에서 실측하지 않은 기능은 사전 기록과 관계없이 미확인으로 둡니다.

이동할 파일은 저장소의 on-client 전체입니다. 필요한 package.json·src·public·student·vendor·학생 문서·비밀 없는 .env.example을 같은 커밋으로 가져옵니다. 이전의 절대 경로는 실행 위치 증거이며 필수 설치 경로가 아닙니다. 새 환경에서는 본인이 정한 새 폴더의 on-client에서 명령을 실행합니다. 번들 Node 절대 경로는 macOS 관측 도구 위치일 뿐 배포 의존성이 아닙니다. 새 환경에서는 package.json 요구 버전 24.19.0의 node를 사용합니다. 이번 환경의 24.22.1 기록은 다른 버전의 지원 선언이 아닙니다.

외부 npm 의존성 선언과 앱 lock 파일은 현재 없습니다. 임의로 의존성을 설치하거나 기존 프로젝트의 node_modules를 복사하지 않습니다. 외부 시스템 연결·AI 자격·조치 DB·공개 조회 대상은 담당자가 승인한 방식으로 별도 준비합니다. 설정 견본만 복제하며 실제 인증 파일은 새 폴더에 무작정 복사하지 않습니다. 제공 실행 도구의 충돌 표시, Windows·요구 런타임·브라우저 확인 부재, 18단계 미완성 및 19·20단계 학생 표시 미구현은 해결된 것으로 표시하지 않습니다.

| 학생이 별도로 보관한 로컬 자료 | 담당자가 정한 접근 제한 저장 위치에 백업하고 목록·시각을 기록. Git·공개 문서에 개인정보나 본문을 추가하지 않음 | 새 위치에서 복원본을 대조하고 기존 자료 유지. 실제 파일 존재와 백업·복원은 이번에 미확인 |
| 접근 제어·XDR 원본 기록 | 원본은 외부 시스템 책임 범위. 학생 화면의 응답은 원본 백업이 아님 | 같은 학생·프로젝트 권한 확인 후 재조회. 원본 서버 보존 정책·복구 권한은 담당자 확인 필요 |
| 조치 이력 DB | src/actions/store.mjs는 담당자가 지정한 기존 SQLite DB에 이력 테이블 사용. DB가 없으면 임의 새 DB로 바꾸지 않음 | 담당자가 쓰기 중단·연결 종료 및 일관된 SQLite 백업 방법을 확인한 뒤 백업. 실행 중 DB 파일만 무작정 복사하지 않음. 경로·권한·스키마·이력 연속성을 별도 복원본에서 확인한 뒤 연결. 실제 DB 설정·백업·복원 시험은 미확인 |
| 인증 보관함·인증서·개인 설정 | 비밀값은 소스 백업에서 제외. src/ai/credential-vault.mjs의 저장은 호스트 보관함 경계이며 고정 로컬 경로를 가정하지 않음 | 담당자의 보관함 복구·재승인 절차 사용. 남의 자격이나 기존 인증 파일을 복사하지 않음. 실제 복원·재승인은 미확인 |
| 브라우저 표시·진행 중 요청 | 화면 상태·메모리의 확인 정보를 영구 백업으로 취급하지 않음 | 새 환경에서 현재 상태를 다시 조회. 새로고침·화면 취소는 원본 기록 삭제나 집행 효과 취소가 아님 |

실제 복원 시에는 먼저 원래 자료와 백업을 보존하고, 별도 복원 폴더를 만든 뒤 버전·대상·권한·데이터 일관성을 확인합니다. 확인 전에는 운영 DB를 교체하거나 집행을 재시도하지 않습니다. 저장소만 복제해 외부 데이터·앱 인증·집행 이력이 복구됐다고 주장하지 않습니다.
